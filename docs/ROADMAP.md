# Garfield — единый ROADMAP (актуализирован 2026-11-02)

В этом файле состояния означают изменения **в коде**, а не подтверждение
исправной работы на компьютере пользователя.

## Журнал запусков и контролируемый повтор — этап 2026-11-02

- [x] Расширение таблицы `scheduled_runs`: поле `detail`, миграция
  существующих SQLite-баз без удаления истории, DPAPI для текста результата.
- [x] Список последних запусков с датой, сценарием, статусом и кратким
  сообщением; автоматические проверки по появлению файла тоже журналируются.
- [x] Вкладка «Журнал» в интерфейсе: просмотр последних 100 записей,
  ручное обновление, переход к плану повторного запуска.
- [x] Команды «журнал заданий» и «повтори неудачный сценарий ID»;
  повтор возможен только для последнего фонового статуса `failed`,
  при наличии сценария и после стандартного подтверждения плана.
- [x] Ручной повтор не переоткрывает исходную запись `failed` и не
  запускается автоматически. Используется текущая конфигурация сценария.
- [x] Регрессионные тесты для журнала, миграции SQLite, повторов,
  файловых событий и отсутствия автоматического исполнения.
- [ ] Проверить на рабочем Windows-ПК и в GUI: реальные ошибки
  планировщика, обновление вкладки, диалог подтверждения и восстановление.
- [ ] Полноценный просмотр деталей, фильтры, пагинация журнала,
  очистка старых записей и наблюдаемость событий в реальном времени.
- [ ] Долговечная очередь файловых событий при остановленном приложении
  и полноценное восстановление зависших `claimed` после сбоев.

## Надёжность заданий и параллельных команд — этап 2026-11-02

- [x] Блокировка одноразового подтверждения планов: одновременные запросы
  GUI и голоса не должны повторно исполнять один и тот же план.
- [x] Таблица SQLite `scheduled_runs` с уникальным ключом

- [x] После перезапуска приложения ежедневный сценарий не повторяется в

- [x] Фоновое расписание ограничено allowlist `system_status`,
  без неявного чтения заметок или файлов.
- [x] Сбой одной проверки не останавливает остальные задания очереди.
- [x] Тесты SQLite-перезапуска, однократности, запрета фонового чтения
  данных и одновременного подтверждения.
- [ ] Тест на реальном Windows-компьютере: перезапуск в момент выполнения,

- [ ] Долговечное отслеживание файловых событий при выключенном приложении:

- [x] Отдельный UI для просмотра статуса фоновых запусков и

## Стабилизация и безопасность — этап от 2026-11-02

- [x] MCP Streamable HTTP (версия протокола 2025-03-26): теперь
  проверяется точный JSON-RPC `id` для каждого ответа. Уведомления
  SSE больше не принимаются за результат `tools/call`.
- [x] Клиент MCP корректно распознаёт `202 Accepted` для уведомления,
  валидирует согласованную версию протокола, `session-id` и каталог
  инструментов с постраничной навигацией (не более восьми страниц).
- [x] Ограничена длина обрабатываемых SSE/JSON-ответов и конфигурации MCP;
  локальные HTTP-запросы не используют прокси из переменных окружения.
- [x] Для локальных моделей Ollama / llama.cpp отключены переменные
  HTTP(S)_PROXY — запросы и содержимое диалога не должны уходить в прокси.
- [x] Vision-запрос ограничен endpoint `/api/generate`;
  при работе с локальной vision-моделью отключено использование системного прокси.
- [x] Конструктор сценариев не позволяет незаметно потерять несохранённые
  изменения при переключении сценариев; перенос шага сбрасывается при
  отпускании кнопки мыши.
- [x] Добавлены регрессионные тесты: SSE с уведомлениями, проверка JSON-RPC
  идентификаторов, постраничный каталог, неподдерживаемая версия MCP,
  запреты прокси и неподходящего vision endpoint.

- [ ] **Полный автономный агент** с динамическим выбором инструментов,

## Как проверить
1. `python -m compileall -q garfield_best.py garfield_flagship.py garfield_agent garfield_dashboard`
2. `python -m unittest discover -s tests -v`
3. `python tools/diagnose_windows.py --mic` на компьютере пользователя.
4. Проверить «посмотри на экран» только с локальным Ollama vision.
5. Протестировать JSON-сценарии и отказ от опасных инструментов.
6. Проверить переключение Vosk/Whisper и прерывание озвучивания.
7. Провести пилотное обновление на отдельной тестовой копии, не на рабочем ПК.

## Правило развёртывания
Автоматические тесты недостаточны для заявления «100% готово».
Следующие версии с новой логикой действий следует выпускать только
после ручного Windows smoke-test и проверки разрешений.
