# Garfield General

Основная пользовательская версия проекта: `garfield_flagship.py`.

`garfield_best.py` содержит ядро ассистента: команды, распознавание речи через Vosk,
озвучку, кэш ответов, историю диалога и подключение к ИИ-провайдерам.

## Возможности

- Современный GUI-dashboard на `customtkinter` с fallback на legacy `tkinter` и консоль.
- Голосовой ввод через Vosk с автопрослушиванием, выбором микрофона, тестом уровня и режимами `continuous` / `wake_word`.
- Озвучка ответов через Piper `ru_RU-irina-medium`, Edge TTS и локальные fallback-голоса Windows.
- Последовательная обработка команд и очередь TTS, чтобы GUI, ответы и озвучка не мешали друг другу.
- Ответы через выбираемый ИИ-провайдер: NVIDIA, OpenAI, Google Gemini, Groq Cloud или xAI Grok.
- Выбор модели в настройках: NVIDIA Llama 3.1, OpenAI GPT-4.1 Mini / GPT-4o Mini, Gemini 2.5 Flash / Flash Lite / Pro, Groq Llama/GPT-OSS, xAI Grok 4.3 / Grok 4.
- Короткая память диалога, кэш ответов, экспорт истории сессии.
- Desktop-команды: браузер, YouTube, интернет-поиск, окна, вкладки, мышь, текст, громкость и яркость.
- Безопасное подтверждение команд выключения, перезагрузки и сна.
- Диагностика Vosk, Piper, ИИ-провайдера, микрофона, вывода, навыков и состояния прослушивания.

## Быстрый запуск

1. Установите Python 3.10+.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Проверьте путь `vosk_model_path` в `garfield_flagship_config.json`.
4. Запустите `Start_Garfild.bat`.

`Start_Garfild.bat` ищет Python в `.venv`, затем в `C:\Python314`, затем через `py` или `python`, и запускает `garfield_flagship.py`.

## Настройка ИИ

В разделе настроек выберите:

- `llm_provider`: `nvidia`, `openai`, `gemini`, `groq` или `xai`.
- `llm_model`: модель из списка для выбранного провайдера.
- API-ключ нужного провайдера или переменную окружения `NVIDIA_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `XAI_API_KEY`.

Рабочий конфиг хранится в `garfield_flagship_config.json`, шаблон без ключей - в `garfield_flagship_config.json.example`.

## Голосовой режим

По умолчанию включен режим `continuous`, автопрослушивание и автоматический выбор микрофона. Если ассистент слышит лишнее, переключите `activation_mode` на `wake_word` и используйте ключевую фразу `гарфилд`.

Основные команды:

- `помощь`
- `диагностика`
- `повтори`
- `что ты услышал`
- `очисти память`
- `очисти кэш`
- `сохрани диалог`
- `включи прослушивание`
- `выключи прослушивание`
- `включи озвучку`
- `выключи озвучку`
- `найди ...`

## Заметки

- Если `pyautogui` недоступен, desktop-команды сообщат об ограничении.
- Если Vosk-модель не найдена, приложение переключится в текстовый режим, если `input_mode` не установлен строго в `voice`.
- Если выбранный ИИ-провайдер недоступен или долго не отвечает, ассистент использует локальный fallback-ответ.

## Локальный ИИ через Ollama

Установите Ollama на Windows и выполните `ollama pull qwen2.5:3b`. В настройках Garfield выберите провайдера `ollama`, модель `qwen2.5:3b` и URL `http://127.0.0.1:11434/api/chat`. API-ключ не нужен. Сервер Ollama запускается отдельно; Garfield не устанавливает и не загружает модели автоматически. Для этого провайдера разрешены только адреса loopback.

## ИИ-агент, память и сценарии (экспериментальная версия)

В этом PR добавлены локальные инструменты, память SQLite и сценарии. Приложение по
умолчанию **не даёт нейросети самостоятельно запускать команды или писать файлы**.

- `агент покажи состояние компьютера` — нейросеть составляет план из доступных инструментов.
- `подтверди план` — выполняет предварительно показанный план (не позднее 120 секунд).
- `отмени план` — отменяет план без исполнения.
- `запомни купить батарейки` — сохраняет заметку в локальной базе.
- `мои заметки`, `найди заметку батарейки`, `забудь заметку 1` — управление заметками.
- `сценарии` — список сценариев.
- `запусти сценарий system-check` — показывает план из сценария перед выполнением.
- `найди в истории слово` — поиск в сохранённой истории (если её сохранение включено).

Пример `garfield_workflows.json.example` скопируйте в `garfield_workflows.json`.
Сценарии задаются JSON-файлом, допускают не более 6 шагов и проходят валидацию.
Планировщик по умолчанию отключён. После включения в настройках он может
**автоматически выполнять только read-only инструменты** из ежедневных сценариев.
Все остальные шаги требуют ручного запуска и подтверждения.

Данные хранятся локально в `%LOCALAPPDATA%/Garfield/assistant.sqlite3`
(на иных ОС — в `~/.garfield`). Папка, в которой агенту разрешено читать текстовые
файлы, — `~/Documents/GarfieldWorkspace`. Автоматическая загрузка этих файлов в
облачный ИИ не производится: пользователь отдельно передаёт содержимое по своему
усмотрению. SQLite не шифрует содержимое; не используйте для секретов.

Для чтения публичных страниц браузером (необязательный инструмент) отдельно:
`pip install playwright` и `playwright install chromium`.
Обратите внимание: отправленный облачной модели текст запроса на составление плана
передаётся выбранному ИИ-провайдеру; для приватных запросов используйте Ollama.

## Безопасное хранение API-ключей на Windows

При сохранении настроек API-ключи теперь защищаются через Windows DPAPI и
записываются в `garfield_flagship_config.json` как `dpapi:...`, а не открытым
текстом. При загрузке старая конфигурация с открытыми ключами ещё читается;
**сохраните настройки**, чтобы зашифровать их. Ключ привязан к учётной записи
Windows и не переносится на другой компьютер. На других ОС сохраняйте ключи
только в переменных окружения (при попытке сохранить непустой ключ в JSON
программа сообщает об ошибке). Сделайте резервную копию исходной конфигурации
до миграции. Заметки и историю SQLite DPAPI не шифрует.

## Альтернативное распознавание faster-whisper

По умолчанию сохранён Vosk. Для русской речи можно отдельно установить
`pip install faster-whisper`, затем выбрать `stt_engine=whisper` и модель
`base` или `small` в настройках и перезапустить Garfield. Первый запуск
может загрузить модель из внешнего репозитория. В offline-среде используйте
локально скачанные веса. Порог уверенности для Whisper эвристический,
не идентичен Vosk; работоспособность с разными микрофонами нуждается в
тестировании на Windows.

## Контролируемое взаимодействие с Windows и файлами

ИИ-агент может предлагать создание новых текстовых файлов и папок внутри
`GarfieldWorkspace` (существующие файлы не перезаписывает). Скриншоты
сохраняются там же; они **не передаются ИИ автоматически**. Список окон и
переключение к точно указанному окну используют необязательный пакет
`pip install pywinauto`. Любой план, включая чтение, требует ручного
подтверждения. Сценарии по расписанию автоматически выполняют только
инструменты категории `read`.

## Установка на Windows одной командой

В PowerShell из папки проекта:
`powershell -ExecutionPolicy Bypass -File .\\setup_windows.ps1`
или с дополнительными компонентами:
`powershell -ExecutionPolicy Bypass -File .\\setup_windows.ps1 -InstallWhisper -InstallBrowser -InstallUIAutomation`

Скрипт создаёт `.venv`, устанавливает зависимости и запускает тесты.
После этого используйте `Start_Garfild.bat`. Он не скачивает Vosk/Piper
автоматически: установите нужные голосовые модели отдельно.

## Дополнительные возможности (PR #2)

### Визуальное понимание экрана, только локально

Введите `посмотри на экран` или `посмотри на экран и объясни ошибку`.
Garfield захватывает уменьшенную копию экрана **только после этой явной команды**
и передаёт её в локальный Ollama, не сохраняя снимок. По умолчанию нужна модель
`llava:7b`; можно изменить через `GARFIELD_VISION_MODEL`. Сначала установите
Ollama и скачайте vision-модель. Не используйте эту функцию на экране с паролями,
банковскими данными или секретными сообщениями: локальный сервер Ollama тоже
должен быть под вашим контролем.

### MCP: локальные расширения с разрешениями

Скопируйте `garfield_mcp_servers.json.example` в `garfield_mcp_servers.json`
и укажите ваш доверенный сервер на `http://127.0.0.1:PORT/mcp` с явным
`allowed_tools`. Команда `mcp серверы` показывает доступные локальные
инструменты. Вручную подтверждённый план может включать инструмент
`mcp_call` с аргументами `server`, `tool` и `arguments` (JSON-строкой).
**Нет доступа к внешним MCP-серверам** и **нет запуска MCP-процессов через stdio**.
Реализован небольшой клиент Streamable HTTP для простых JSON/SSE-ответов;
сложные реализации и авторизация MCP требуют отдельной совместимости.

### Восстановление сценариев и конструктор

При ошибке сценария Garfield предлагает `исправь план`: ИИ составляет
альтернативные шаги для ещё не выполненной части. Исправленный план снова
требует подтверждения. Повтор уже успешных шагов запрещён. Если последовательность
создала новые текстовые файлы или пустые папки, при ошибке программа пытается
откатить только эти новые объекты и не удаляет изменённые пользователем файлы.
Откат не отменяет сообщения, действия внешних MCP-инструментов и другие побочные
эффекты. В разделе «ИИ-агент» → «Сценарии» есть кнопка «Конструктор»:
добавление, удаление и перетаскивание шагов, условия запуска и проверка перед
сохранением. Без подтверждения в фоне выполняются только `read`-действия.
Новый триггер `when_file_created` принимает путь внутри `GarfieldWorkspace`.

### Дополнительные локальные модели

В настройках можно выбрать `llamacpp`: локальный совместимый сервер по
адресу `http://127.0.0.1:8080/v1/chat/completions`. Нужен отдельно
запущенный llama.cpp server с моделью GGUF. Адреса вне loopback запрещены.

Для Ollama введите `скачай модель qwen2.5:3b`, затем
`подтверди загрузку модели`. Поддерживается ограниченный список имён.
Загрузка может быть большой; приложение не скачивает модели без подтверждения.

### Обновления

`проверь обновления` проверяет GitHub, не меняя файлы. После явного
`подтверди обновление` выполняется только безопасное быстрое продвижение
(`git merge --ff-only`) из официального источника, если ваша ветка `main`
и рабочая папка без изменений. Настройка «Ежедневно проверять GitHub-обновления»
включает фоновые **проверки**, но никогда фоновую установку. Работает только
для Git-копии репозитория, не для EXE/ZIP. После обновления перезапустите Garfield.

### Личная память Windows

Новые SQLite-записи с заметками, диалогами и журналами действий защищаются
через DPAPI текущей учётной записи Windows. При первом запуске выполняется
миграция старых незашифрованных записей. Резервные копии, созданные до миграции,
остаются незашифрованными. DPAPI не защищает от программ, запущенных от того же
пользователя, и не позволяет переносить зашифрованную базу на другой компьютер.
На Linux/macOS SQLite остаётся в открытом виде. Автоматической облачной
синхронизации нет.

### Windows-сборка, диагностика

После `setup_windows.ps1` можно собрать предварительный пакет командой
`powershell -ExecutionPolicy Bypass -File .\\build_windows.ps1`.
При установленном Inno Setup ISCC будет собран **неподписанный** EXE-установщик.
Публикация официально подписанного файла требует действительного сертификата
издателя и проверки цепочки доверия. Не выдавайте тестовую сборку за релиз.

На Windows выполните `python tools/diagnose_windows.py --mic`, чтобы получить
локальный отчёт о библиотеках, устройствах и уровне сигнала микрофона.
Аудио не отправляется на сервер и не сохраняется.

## Исправления MCP и локальной приватности (2026-11-02)

MCP-клиент использует только конфигурацию `garfield_mcp_servers.json`
и явно разрешённые инструменты на локальном сервере с URL вида
`http://127.0.0.1:9000/mcp`. Важно: сервер MCP запускается отдельно,
с собственными правами, поэтому добавляйте только доверенные серверы.

- Поддерживаются JSON-ответы и SSE-сообщения, включая уведомления о
  прогрессе. Результат действия принимается **только** при совпадении
  `JSON-RPC id` с запрошенным методом; последнее событие потока
  само по себе больше не считается ответом.
- Уведомление `notifications/initialized` может вернуть пустой
  `202 Accepted`, как предусмотрено протоколом.
- Проверяются `protocolVersion=2025-03-26`, идентификатор сессии и
  постраничные каталоги `tools/list` (до восьми страниц).
- Для MCP, Ollama и llama.cpp отключено использование системных
  прокси. Локальный vision-анализ использует только
  `/api/generate` на loopback и не должен пересылать изображение
  через переменные `HTTP_PROXY` / `HTTPS_PROXY`.
- Конструктор сценариев предупреждает о несохранённых правках при
  переключении сценария; при перетаскивании сбрасывает выбранную
  перемещаемую строку после отпускания кнопки мыши.

Ограничения: MCP-клиент пока **не является универсальной реализацией
всех версий MCP** — не поддерживает удалённые серверы, их авторизацию,
серверные запросы к клиенту и полноценный обработчик длительных потоков.
Для исходного протокола см. спецификацию
https://modelcontextprotocol.io/specification/2025-03-26/basic/transports .
Проверки CI используют имитации ответов MCP, а не реальный сервер.
Проверки GUI с экраном и мышью также необходимы на Windows.

## Хранение и удаление истории (обновление 2026-11-02)

По умолчанию завершение Garfield **больше не создаёт текстовый файл с
диалогом**. При включённой опции сохранения истории сообщения записываются
в локальную SQLite-базу; на Windows содержимое защищено через DPAPI.
Экспорт текстового диалога выполняется **только вручную** через кнопку
«Сохранить историю» / «Экспортировать» или команду «сохрани диалог».
Полученные TXT/JSON-файлы **не зашифрованы**, их нужно защищать отдельно.

Для удаления сохранённой истории скажите «удали сохранённую историю», затем
«подтверди удаление истории» (не позднее 120 секунд). Для удаления всех
заметок: «удали все заметки», затем «подтверди удаление заметок». Команда
«отмени удаление» сбрасывает запрос. Очистка **текущей сессии** в интерфейсе
не удаляет сохранённые ранее записи из SQLite — для этого нужны отдельные
команды. Старые `garfield_session_history.txt`, `garfield_session_history_export.*`,
архивы и резервные копии Garfield автоматически не удаляет. Если раньше
автоматически создавались открытые текстовые файлы с личными данными,
удалите их вручную после проверки содержимого.

Операция удаления перестраивает свободные страницы SQLite через VACUUM, но
не может гарантировать физического стирания файлов в SSD, резервных копиях
или снимках системы.

## Надёжность сценариев и подтверждений (2026-11-02)

- **Одно подтверждение — одно исполнение.** Запуск подтверждённого плана
  атомарно забирает ожидающее подтверждение. Повторное «подтверди план»,
  поступившее одновременно из GUI/голоса, не запускает шаги повторно.
  Пока план выполняется, другой план не может заменить его.
- **Ежедневное расписание запоминает запуск.** В SQLite появилась таблица
  `scheduled_runs`. До исполнения ежедневного сценария создаётся уникальная
  запись по идентификатору сценария, дате и времени. После исполнения она
  помечается как `succeeded` или `failed`. После перезапуска Garfield тот
  же сценарий за тот же день не выполняется повторно.
- **Семантика расписания — не более одного запуска, не гарантированная
  доставка.** При аварийной остановке после резервирования записи, но до
  выполнения действий, сценарий не будет перезапущен автоматически. Ошибка
  выполнения также не вызывает бесконтрольных повторов. Пользователь может
  запустить сценарий вручную через подтверждение.
- **Автоматически исполняется только `system_status`.** Даже если инструменты
  `read_file`, `list_files` или `recall_notes` относятся к категории
  чтения, они больше не запускаются фоновым расписанием без подтверждения.
  Такой сценарий разрешается запускать вручную через `запусти сценарий ID`
  и `подтверди план`.
- **Сбой одного сценария не блокирует остальные.** Ошибки отдельных
  заданий сохраняются в журнале; дальнейшие задания продолжаются.
- **Триггер появления файла:** по-прежнему отслеживает переход от
  отсутствующего файла к существующему при работающей программе.
  Отслеживание этого события не является долговечным при выключенном
  приложении, а повторные короткие события между проверками могут пропускаться.

Сценарии в фоне по умолчанию выключены. Для их запуска включите настройку
«Расписание безопасных проверок». Пример штатного фонового сценария —
`system_status` по времени. Прочие инструменты требуют предварительного
просмотра плана и ручного подтверждения.

## Журнал фоновых заданий и ручной повтор (2026-11-02)

В панели **«ИИ-агент» → «Журнал»** можно увидеть последние фоновые запуски,
включая ежедневные проверки и обнаруженные при работающей программе
события появления файла. Для каждого запуска выводятся дата/время, ID
сценария, тип события, состояние (`claimed`, `succeeded`, `failed`) и
краткое описание ошибки или результата. История хранится в SQLite;
на Windows текст ошибки шифруется DPAPI, как и другие записи. Для новых
установок всё создаётся автоматически, существующая база получает
дополнительный столбец `detail` без удаления прежних записей.

Команды:
- `журнал заданий` — последние 15 записей в текстовом виде;
- `повтори неудачный сценарий ID` — **только показывает план** повторного
  запуска, если последний фоновый запуск данного ID имеет состояние `failed`;
- `подтверди план` — выполняет отображённый план после отдельного согласия;
- `отмени план` — отменяет подготовленный повтор.

В GUI для повтора укажите ID сценария в разделе «Журнал» и нажмите
«Показать план повтора». Затем отдельно подтвердите выполнение во
вкладке «ИИ-агент». Для ручного повтора используется **текущая**
конфигурация сценария, а не сохранённая историческая версия.
Если сценарий удалён, повтор недоступен. Ошибочный автоматический запуск
по расписанию **не перезапускается автоматически** — остаётся правило
`at-most-once`. Ручной повтор не заменяет и не удаляет историческую
запись `failed`, а результаты самого ручного плана продолжают записываться
в журнал исполнений агента.

Ограничения: статус `claimed` после аварийного завершения процесса не
является подтверждением того, что действие фактически выполнялось; по
умолчанию запуск не повторяется автоматически. Файловый триггер фиксируется
только при запущенном Garfield и не воспроизводит пропущенные изменения.
Журнал показывает последние 100 записей в GUI. Для корректной проверки
работы реального планировщика и интерфейса необходим Windows smoke-test.

## Фильтры журнала и проверка зависших запусков — 2026-11-02

Вкладка **«ИИ-агент» → «Журнал»** теперь отображает по 25 запусков
на странице. Можно выбрать состояние («Все», «Ожидает», «Успешно»,
«Ошибка»), указать точный ID сценария и переключаться между страницами.
Отображается количество найденных записей. Фильтры применяются к SQLite
через параметризованные SQL-запросы; данные всех страниц не загружаются
в память графического интерфейса. Доступ к содержимому сообщений и журналов
сохраняет прежнюю Windows DPAPI-защиту.

Если запись сохранилась со статусом `claimed` более 30 минут,
интерфейс помечает её **«ТРЕБУЕТ ПРОВЕРКИ»**. Это **не означает**, что
сценарий завершился с ошибкой: он может выполняться в другом процессе,
быть остановлен аварийно или зависнуть в системном вызове. Просмотр
журнала не меняет его статус и **не запускает задачу повторно**.

Для неуспешных запусков со статусом `failed` по-прежнему доступен
отдельный ручной повтор после просмотра и подтверждения плана.
Для записей `claimed` автоматический и полуавтоматический повтор
намеренно заблокирован до подтверждения фактического состояния задачи.

Ограничение: интерфейс использует смещение страниц, поэтому при
одновременном появлении новых записей отдельные страницы могут менять
состав. Полное тестирование интерфейса на пользовательском Windows-ПК
ещё не выполнено.

## Ревизия фоновых заданий и хранение истории — ноябрь 2026

**1. Диагностика незавершённых заданий.** Каждое новое фоновое задание
получает уникальный ID сессии Garfield, PID владельца и, при наличии
пакета `psutil`, время создания процесса. Во время выполнения
записывается `heartbeat` каждые 5 секунд. В журнале `claimed` считается
подозрительным, если подтверждение активности отсутствовало более
30 минут. Для подозрительных запусков программа пытается установить,
существует ли тот же процесс (PID + время создания), и сообщает
`owner_alive`, `owner_not_running` или `unknown`. Изменение состояния
владельца **не доказывает, что внешнее действие завершилось**: дочерний
процесс или сторонний сервис могли продолжить работу. Garfield не
превращает `claimed` в `failed` и никогда не перезапускает их
автоматически. Без `psutil`/метаданных отображается `unknown`.
Существующие старые записи остаются доступными без метаданных.

**2. Очистка журнала по сроку хранения.** В разделе
**«ИИ-агент» → «Журнал»** укажите срок хранения от 1 до 3650 дней.
Кнопка «Проверить очистку» показывает число подходящих записей; для
удаления отдельно нажмите «Подтвердить очистку» в течение 120 секунд.
Аналогичные команды:

```text
очисти журнал старше 90 дней
подтверди очистку журнала
отмени очистку журнала
```

Удаляются **только** записи `succeeded` и `failed` старше указанного
срока. `claimed` остаются в базе независимо от возраста. Очистка
**не запускается по расписанию**, не затрагивает заметки и диалоги,
не удаляет резервные копии. После удаления выполняется SQLite VACUUM;
это не гарантирует физическое стирание SSD или снимков системы.

**3. Начало модульного разделения.** Класс `TTSQueue` вынесен из
`garfield_flagship.py` в `garfield_runtime/tts_queue.py`;
цикл фонового планировщика и heartbeat — в
`garfield_runtime/scheduler.py`, а консервативная оценка владельца —
в `garfield_runtime/schedule_health.py`. Старый интерфейс
`FlagshipRuntime` сохранён. Основные старые части `garfield_best.py`,
Tk GUI и обработчик команд ещё требуют дальнейшего разделения.

Проверка на реальном Windows-компьютере остаётся обязательной:
сон/пробуждение, убийство процесса посреди задания, UI и аудиодрайверы
в автоматическом CI не испытываются.
